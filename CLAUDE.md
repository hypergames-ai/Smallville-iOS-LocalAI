# Smallville (iOS) — on-device generative agents

Port of Stanford's *Generative Agents* ("Smallville", Park et al. 2023) to an iOS 27 app that runs entirely on-device with Apple's Foundation Models framework. Non-commercial, open source. Read `docs/ARCHITECTURE.md` before touching the core; `docs/DECISIONS.md` says why things are the way they are.

## Non-negotiables

- **Offline only.** No networking code anywhere: no `URLSession`, no sockets, no `PrivateCloudComputeLanguageModel`, no third-party `LanguageModel` providers. If a task seems to need the network, stop and say so instead of working around it.
- **Foundation Models only** for cognition (`SystemLanguageModel`, on-device). Every model output goes through a `@Generable` type; never parse free text with regexes or string splitting.
- **Budgets are design constraints:** at most 3,000 tokens per prompt (instructions + prompt + schema + response), and about 45 model calls per agent per game-day. If a change would raise either, say so before implementing.
- **No third-party art in git.** `Assets/ThirdParty/` is gitignored and populated by `scripts/fetch-assets.sh`. Never commit it, never copy files out of it, never hardcode paths into it; load through `AssetCatalog` so the original Stanford repo stays the distribution point.
- **Core stays pure.** `Sources/SmallvilleCore` imports `Foundation` only: no FoundationModels, no UIKit/SpriteKit/SwiftUI, no Combine. The core must build and test on any Mac.

## Layout

- `Package.swift` — SwiftPM package `SmallvilleKit`: `SmallvilleCore` (simulation, memory stream, retrieval, storyline detection), `SmallvilleFM` (Foundation Models adapter), `smallville-run` (headless CLI runner), `SmallvilleCoreTests`.
- `App/` — iOS app (SwiftUI + SpriteKit). The Xcode project is generated by XcodeGen from `App/project.yml`; never edit the `.xcodeproj` by hand, edit `project.yml` and regenerate.
- `docs/` — `ARCHITECTURE.md`, `DECISIONS.md`, `PROMPTS.md` (how to work with the agent), `SETUP-CHECKLIST.md`.
- `scripts/` — hook scripts and `fetch-assets.sh`.

## Commands

- Build and test the core: `swift build` and `swift test`
- Headless sim with the stub brain (works anywhere): `swift run smallville-run --minutes 60 --agents 3`
- Headless sim on the Mac's on-device model: `swift run smallville-run --minutes 60 --agents 3 --fm` (needs macOS 27 with Apple Intelligence enabled)
- iOS project: `cd App && xcodegen generate`, then build and run through XcodeBuildMCP or Xcode
- Format: `swift format --in-place <file>` (a hook does this after every edit)

## Conventions

- Swift 6 language mode with strict concurrency. Simulation state lives in actors; anything crossing an actor boundary is `Sendable`.
- No `!` force unwraps and no `try!` under `Sources/`. Use `guard` and throw a typed error.
- Every public type has a one-line doc comment saying what it is for.
- Sim time is `SimTime` (minutes since start). One tick is 10 game-minutes, as in the original.
- Logging through `os.Logger` with subsystem `smallville`. `print` is allowed only in `smallville-run`.
- Determinism: anything random takes a seed, and a run must replay from (seed, whispers).
- Tests use Swift Testing (`import Testing`) against `StubBrain` or a scripted brain. `swift test` never calls the real model.

## How to work here

- For anything that touches more than one target, start in plan mode and show the plan before editing.
- Verify before reporting done: `swift test` always; for simulation changes also run `smallville-run` and paste the budget summary JSON into your report.
- Prefer small, reviewable diffs: one commit per logical change, and don't commit unless asked.
- Check Apple API details with the `apple-docs` subagent before writing against FoundationModels, SpriteKit, or SwiftUI; the framework changed between iOS 26 and 27. Mark anything you could not verify with `// VERIFY:`.
- Ask before adding a dependency, a target, or an MCP server.
- Don't fix a problem by relaxing a rule in this file or in `.claude/rules/`; propose the rule change and wait.

## Compact instructions

When compacting, keep: the current task's goal and its acceptance test, the files changed this session, open `// VERIFY:` items, and the latest budget summary. Drop tool output and exploratory file reads.
